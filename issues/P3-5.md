# P3-5 — sendErrorHeaders() uses hardcoded HTTP/1.1 protocol in the header() …

## Finding / 问题

- EN: sendErrorHeaders() uses hardcoded HTTP/1.1 protocol in the header() call; on HTTP/2 requests this sends an incorrect status line. Should use http_response_code(500) instead.
- 中文: sendErrorHeaders() 在 header() 调用中使用硬编码的 HTTP/1.1 协议；在 HTTP/2 请求下会发送错误的状态行。应改用 http_response_code(500)。
- Where / 位置: `src/DebugPage.php:166`
- Verification / 验证: static / 仅静态推断

- 2026-10-01 · `owner — migears-debug` · `fixed` — EN: the code fact is real, the stated HTTP/2 consequence is not; took the recommended form anyway, which also removes the workspace's last literal status line.
  - Real: `sendErrorHeaders()` did pin the status line to HTTP/1.1 (`src/DebugPage.php:368` before this pass).
  - Not reproducible: "on HTTP/2 requests this sends an incorrect status line". HTTP/2 has no status line — the status travels as the `:status` pseudo-header. Probes (PHP 8.5.10): php-cgi emitted byte-identical `Status: 500 Internal Server Error` for `header('HTTP/1.1 500 Internal Server Error')`, for `header('HTTP/2 500 Internal Server Error')` and for `http_response_code(500)`, with `SERVER_PROTOCOL=HTTP/1.1` and with `=HTTP/2.0` alike — in its default mode (`cgi.rfc2616_headers=0`) the gateway never sees the token. It appears only in the legacy NPH mode (`cgi.rfc2616_headers=1`), which by definition writes an HTTP/1.x status line — an HTTP/2 request cannot reach it.
  - What the token does do, and why the change is right: the literal form pins the response protocol whatever the connection speaks. `php -S` with the module, an HTTP/1.0 request, before the fix: `HTTP/1.1 500 Internal Server Error`; after: `HTTP/1.0 500 Internal Server Error`, and `HTTP/1.1 500 …` for a 1.1 request — the SAPI now chooses.
  - `src/DebugPage.php:365-377` now sets the code with `http_response_code(500)`. That is the workspace idiom: `migears-web/src/Response.php:99` is the only other place in the tree that sets a status, and it does the same; this module was the sole holder of a literal status line.
  - Regression test: `tests/DebugPageTest.php:441 testErrorStatusLineFollowsTheConnectionProtocol` — starts the built-in server on a free loopback port with a router that registers DebugPage and throws, sends a raw `GET / HTTP/1.0` and asserts the status line. Fail-without-fix proof: restoring `header('HTTP/1.1 500 Internal Server Error')` fails it at `tests/DebugPageTest.php:498` with expected `HTTP/1.0 500 Internal Server Error`, actual `HTTP/1.1 500 Internal Server Error`; restored, the suite is green (39 tests).
